# Reproducibility contract

## Scope

The public repository must support reproduction of the numerical evidence and
all nine figures in the manuscript without access to the private development
repository, sibling checkouts, historical experiment branches, or previously
computed result directories.

The target figures are:

1. `navigation_open_loop.pdf`
2. `navigation_three_panel.pdf`
3. `many_obstacles_equal_budget.pdf`
4. `pendulum_closed_loop.pdf`
5. `pendulum_landscape.pdf`
6. `arm_closed_loop_final_postures.pdf`
7. `arm_landscape.pdf`
8. `arm_posture_grid.pdf`
9. `horizon_sweep_cost.pdf`

## Explicit non-goal: timing reproduction

Control-cycle timing measurements are machine-dependent and are not rerun by
the full numerical reproduction workflow. Published timing records may be
included as archival manuscript inputs, but they must be clearly labeled as
measurements from the original hardware. They must not be presented as outputs
that another machine is expected to reproduce.

Timing code, host-specific acceptance gates, GPU model locks, and timing-based
budget-selection history are not part of the public execution path. The final
rollout budgets selected for the manuscript are fixed directly in the public
configuration.

## Supported workflows

### Frozen-data figure replay

A short workflow regenerates the nine figures from compact audited inputs. It
must not run controller simulations. Its purpose is to let readers inspect the
plotting code and confirm how manuscript figures are constructed.

Interface:

```bash
uv sync --frozen
uv run python reproduce.py --source frozen
```

### Full numerical reproduction

The full workflow starts from an empty output directory and performs:

1. environment and configuration validation;
2. nominal closed-loop campaigns;
3. post-episode free-energy evaluation;
4. parameter-sensitivity campaigns;
5. prediction-horizon campaigns;
6. navigation, pendulum, and planar-arm landscape calculations;
7. aggregation and manuscript-claim checks;
8. generation of the nine figures.

Interface:

```bash
uv sync --frozen --extra cuda --group dev
uv run python reproduce.py --source simulation --execute --gpu-index 0 \
  --output artifacts/full-run
```

The command must print a plan and write nothing unless `--execute` is supplied.
Long runs must be resumable by explicit stage and must never silently reuse
outputs from a scientifically incompatible configuration.

## Numerical agreement policy

Bitwise identity is not required across GPU models, JAX/XLA versions, or
operating systems. Reproduction is judged using all of the following:

- identical task definitions, seeds, rollout budgets, temperatures, horizons,
  controller allocations, disturbance construction, and evaluation sample
  counts;
- identical handling of projected actuator inputs and hard state constraints;
- no deletion or replacement of failed trials based on their outcomes;
- complete expected trial counts;
- finite-value, collision, success, route-selection, and clearance checks;
- agreement of aggregate statistics within predeclared absolute or relative
  tolerances;
- agreement of the qualitative manuscript comparisons used in the claims;
- successful generation of all nine figures.

The tolerances are stored in
`data/reference/verification_targets.json`. They were computed and written
before the independent public reproduction run and may not be changed after
inspecting the new results. Nominal median tolerances combine a relative floor
with a fixed-seed bootstrap deviation; sensitivity and horizon tolerances use a
relative floor and the published interquartile spread. Timing is absent from
all acceptance checks.

## Scientific campaigns

### Nominal comparison

The final comparison contains four tasks:

- Navigation
- Many Obstacles
- Pendulum
- Planar Arm

It compares MPPI, multi-start MPPI, CBO-MPC, and CBO-MPPI at equal per-control-
step rollout budgets. The public configuration stores the final budgets
directly; it does not repeat the machine-dependent timing campaign that was
used during development to choose them.

### Parameter sensitivity

The sensitivity campaign varies the CBO inverse temperature and the normalized
drift-diffusion ratio while preserving the final nominal task definitions and
rollout budgets.

### Prediction horizon

The horizon campaign compares MPPI, multi-start MPPI, and CBO-MPPI over the
frozen horizon grids for Navigation, Pendulum, and Planar Arm.

### Landscapes and diagnostic figures

Landscape calculations must be generated from explicit task configurations and
fixed seeds. A landscape may use a trajectory generated by an earlier stage of
the same public workflow, but must not import a private or historical result
artifact.

## Clean-repository requirements

The public repository must not depend on or expose:

- private development branches or historical commit identifiers;
- archived tuning and hypothesis-screening scripts;
- coauthor review records or local working notes;
- machine hostnames, usernames, absolute paths, or private checkout names;
- source checkouts outside the repository;
- credentials or environment-specific secrets.

The initial public Git history is created independently from the development
repository. Files are transferred by an explicit allowlist rather than by
removing unwanted files from a development checkout.

## Required validation

Before publication, a fresh clone must pass:

1. package installation from the lock file;
2. unit and smoke tests on CPU;
3. frozen-data regeneration of all nine figures;
4. configuration-manifest and input-checksum validation;
5. at least one GPU smoke trial for every task and controller family;
6. resumption tests using an interrupted small campaign;
7. a full numerical reproduction in a new output directory;
8. comparison against the predeclared numerical tolerances;
9. scans for secrets, absolute paths, private repository names, and unintended
   metadata.

The complete GPU campaign is too expensive for ordinary continuous integration.
CI therefore runs unit tests, CPU smoke tests, manifest checks, and frozen-data
figure replay; the full campaign is recorded as a separately verified release
artifact.
